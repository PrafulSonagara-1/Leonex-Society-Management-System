Getting Started

Leonex SSMS is a Smart Housing Society Management System. It digitises the daily operations of an Indian housing society — maintenance billing, gate security, complaints, amenity bookings, notices, expenses, polls, events, documents and emergency alerts — across four dedicated role portals.

  1. Open Sign In and pick a 1-Click Demo preset (Admin, Resident, Guard or Committee).
  2. You land directly on that role’s portal, pre-loaded with realistic demo society data.
  3. Explore every module — payments are clearly marked simulations, so nothing costs real money.
New self-registrations start in Pending status and must be approved by an Admin before the account can sign in — mirroring a real society’s verification flow.

Core Modules (v4.0)

Maintenance & Billing

Admin generates monthly bills for all flats; residents pay via a clearly-labelled demo UPI/Card flow and receive printable receipts. Collection stats are tracked per month.

Complaints

Residents raise complaints; Admin assigns staff and moves them through the lifecycle: Open → Assigned → In Progress → Resolved → Closed. Every step appends a timeline entry.

Visitor Security

Guards log visitors of type Guest, Delivery, Cab, Service Provider, Staff or Other with the flow Pending → Approved → Checked In → Checked Out (or Rejected). Residents can pre-approve guests for faster entry.

Amenities

Book the Clubhouse, Community Hall, Tennis Court and more with automatic double-booking prevention.

Notices

Official society circulars published by Admin/Committee and surfaced in every portal and the notification center.

Expenses

Society expense ledger with categories, amounts and monthly totals — visible to Admin and Committee for transparent accounting.

Polls

Community votes with double-voting blocked via a per-poll voter list. Results update live as members vote.

Events

Create and promote society gatherings, festivals and meets, with dates and venues visible to all residents.

Documents

Central repository for society records — bylaws, forms, circulars and certificates — managed by Admin.

Emergency SOS

Raise society-wide emergency alerts (fire, medical, security) and resolve them once handled. Alerts surface across portals.

Family & Vehicles

Residents maintain a family member registry and register their vehicles for gate and parking records.

Parking Slots

Visual slot grid — Admin assigns and releases slots, mapping vehicles to owners and flats.

Notifications

A universal notification center: stored notifications plus derived ones (visitors at the gate, unpaid bills, pending approvals) with approve/deny actions and unread badges.

Audit Logs & Reports

Every significant action is written to an audit trail (who, what, when). Monthly billing and collection stats power the committee reports, and global search spans all modules.

Admin Control Center

The Admin portal has full executive control over society operations:

  • Registrations: Approve or reject pending accounts; allot towers, flats and roles.
  • Billing: Generate monthly maintenance bills, track paid/unpaid dues and view collection stats.
  • Complaints: Assign complaints to staff, add notes and move statuses along the timeline.
  • Expenses & Records: Record society expenses, manage notices, events, documents and parking slots.
  • Oversight: Review the audit log, respond to emergency alerts and monitor every module.

Resident Portal

Residents manage their home, dues and community life:

  • Maintenance: View monthly bills, pay via the demo payment flow and download receipts.
  • Complaints: Raise issues and follow the resolution timeline from Open to Resolved.
  • Visitors: Pre-register guests for quick gate entry and approve/deny gate requests in real time.
  • Community: Book amenities, vote in polls, see notices and events, and manage family members & vehicles.
  • Emergency: Raise an SOS alert that reaches guards and admins immediately.

Gate Security Guide

Security Guards run the gate from a focused console:

  • Visitor passes: Register guests, deliveries, cabs, service providers and staff with destination flat and purpose.
  • Approvals: Send entry requests to residents and watch approvals arrive live; pre-approved visitors skip the wait.
  • Check-in / Check-out: One tap each way — the visitor log keeps exact in/out times.
  • Vehicles & SOS: Record vehicle entries and respond to emergency alerts raised in the society.

Committee Member Dashboard

Committee members get governance-level visibility:

  • Financials: Monthly collection stats and the society expense ledger at a glance.
  • Engagement: Run polls, publish notices and oversee society events.
  • Oversight: Browse complaint trends, visitor statistics and the full audit trail.

Tech Stack

  • Server: Node/Express (server.js) serving static pages plus optional API endpoints. No build step, no package installs needed to run.
  • Frontend: Vanilla HTML/CSS/JavaScript multi-page app — no frameworks.
  • UI libraries (CDN): Bootstrap 5.3.2, FontAwesome 6.4.2, Chart.js for dashboard charts.
  • Data engine: SystemDB (js/db.js) — a localStorage-persisted store seeded from data/seed.json. Session user lives in sessionStorage under ssm_current_user.
  • Auth: js/firebase-auth.js tries the Express /api/auth/* endpoints first, then falls back to a client-side demo login for static hosting. Firebase compat SDK powers Google Sign-In.
  • PWA: Web manifest + service worker for installability and offline support.
  • Design system: Deep navy/slate surfaces with a royal-blue accent, plus the SHUI component helpers in js/ui.js (tables, badges, toasts, confirm dialogs, KPI cards).

API & Data Architecture

The Express server exposes these endpoints:

GET  /api/health — service health check
POST /api/auth/login — email/username + password → JWT token + user
POST /api/auth/register — create account (Pending until Admin approves)
POST /api/auth/google — Google OAuth token exchange
Dual architecture: when the API is unreachable (e.g. static hosting), the auth layer transparently falls back to the local SystemDB demo mode, so the full product remains explorable without a server.

Client-side, SystemDB manages these collections:
